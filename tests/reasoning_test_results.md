# OpenRouter模型推理能力测试报告

## 测试概述

本报告汇总了对14个OpenRouter免费模型推理能力的测试结果。测试使用了3道不同类型的中文推理题，包括逻辑谜题、数学计算和概率问题，旨在评估模型的推理能力、输出准确性以及流式输出支持情况。

## 测试方法

### 测试环境
- **API端点**：https://openrouter.ai/api/v1/chat/completions
- **推理配置**：`{"effort": "high", "exclude": false}`
- **超时时间**：120秒
- **测试模式**：非流式和流式两种模式

### 测试题目

#### 题目1：逻辑谜题
> 有三个人 A、B、C，其中恰好有一个人说真话。
> A 说："B 说了谎。" B 说："C 说了谎。" C 说："A 和 B 都在说谎。"
> 问：谁在说真话？
> 输出格式：只输出一个字母 A 或 B 或 C。

**正确答案**：B

#### 题目2：数学计算
> 请先在心里算：$(37 × 19) - (25 × 17)$ 的结果。但输出时：只允许输出 YES 或 NO，判断结果是否为偶数。
> 输出格式：只输出 YES 或 NO（大写），不要任何解释。

**正确答案**：YES（计算结果为278，是偶数）

#### 题目3：概率问题
> 有三只盒子：盒 1：2 金盒 2：2 银盒 3：1 金 1 银随机选一个盒子，再随机从中摸出一枚硬币，发现是金。问：另一枚也是金的概率是多少？
> 输出格式：只输出最简分数（如 $2/3$）。

**正确答案**：$2/3$

## 推理能力分析

### 推理质量评估

1. **优秀**：模型能够清晰地展示推理步骤，逻辑连贯，结论正确
2. **良好**：模型能够展示基本推理过程，但可能不够详细或存在轻微逻辑跳跃
3. **一般**：模型能够得出正确结论，但推理过程不完整或难以理解
4. **较差**：模型无法展示有效推理过程，或结论错误

### 流式输出支持

- **完全支持**：9个模型在流式和非流式模式下都能正常输出推理内容
- **部分支持**：2个模型仅在流式模式下能输出推理内容
- **不支持**：3个模型测试失败，无法评估

### 推理过程特点

1. **逻辑谜题**：大多数模型采用假设法，逐一验证每个人的陈述，最终确定谁在说真话
2. **数学计算**：模型通常分步计算两个乘积，然后相减，最后判断奇偶性
3. **概率问题**：模型主要使用贝叶斯定理或枚举法进行推导，得出最终概率

## 结论与建议

### 主要发现

1. **高支持率**：78.6%的测试模型支持推理参数，能够返回推理过程
2. **一致性**：在支持推理的模型中，约82%的模型在两种模式下都能正常工作
3. **准确性**：所有成功测试的模型都能得出正确答案
4. **质量差异**：不同模型的推理质量存在差异，优秀模型能提供更清晰、更详细的推理过程

### 推荐模型

根据测试结果，以下模型表现最为出色，推荐用于需要推理能力的应用场景：

1. **arcee-ai/trinity-mini:free**：全面支持推理，推理质量优秀
2. **nvidia/nemotron-nano-12b-v2-vl:free**：全面支持推理，推理质量优秀
3. **alibaba/tongyi-deepresearch-30b-a3b:free**：全面支持推理，推理质量优秀
4. **nvidia/nemotron-nano-9b-v2:free**：全面支持推理，推理质量优秀

### 应用建议

1. **前端展示**：对于需要在前端展示推理过程的应用，建议使用流式输出模式，提供更好的用户体验
2. **推理质量**：根据应用需求选择合适推理质量的模型，关键决策场景建议使用推理质量优秀的模型
3. **模型选择**：考虑到测试失败的情况，建议在实际应用中添加模型容错机制，当一个模型失败时自动切换到备用模型
4. **成本优化**：所有测试的模型均为免费模型，可根据推理质量和性能选择最适合的模型

## 1. 用户场景和需求描述

### 1.1 用户场景

**场景 1：用户想实时看到思考过程**
- 用户发送问题后，Stage1 主回答区顶部实时追加思考步骤（title + detail）。
- 思考过程始终展开，用户可手动折叠/展开。

**场景 2：用户只关心答案**
- 若模型不支持 thinking，或 thinking 未触发，思考区不显示。
- 回答仍正常流式输出。

**场景 3：多人并行回答**
- 多个议员同时流式输出，思考过程与回答按议员分隔显示。
- 不要求跨议员的严格顺序，仅保证单议员内部顺序。

**场景 4：刷新后回看**
- 用户刷新页面后，仍能展开当时的思考过程。

### 1.2 核心需求（已确认）

| 需求编号 | 需求描述 | 优先级 |
|---|---|---|
| REQ-001 | 思考过程显示标题 + detail，结构与 demo 一致 | P0 |
| REQ-002 | 思考区显示在 Stage1 主回答区内，不在右侧抽屉 | P0 |
| REQ-003 | 思考区默认展开，用户手动折叠/展开 | P0 |
| REQ-004 | Stage1 回答流式输出 | P0 |
| REQ-005 | 模型不支持 thinking 时不显示思考区 | P0 |
| REQ-006 | 思考过程可持久化、刷新后可回放 | P0 |
| REQ-007 | 自动滚动仅在用户未主动滚动时触发 | P0 |

### 1.3 非功能性需求

| 需求编号 | 描述 | 优先级 |
|---|---|---|
| NFR-001 | 事件协议无歧义、可扩展 | P0 |
| NFR-002 | UI 更新节流，避免卡顿 | P1 |
| NFR-003 | 和现有架构兼容（StageContentArea 为主渲染入口） | P0 |
| NFR-004 | 单会话并发 ≤ 10 议员时仍流畅 | P1 |

## 3. 详细技术方案

### 3.1 协议规范：SSE 事件与字段定义

#### 3.1.1 事件总览

| 事件类型 | 方向 | 触发时机 | 是否新增 |
|---|---|---|---|
| meta | BE -> FE | 会话开始解析后 | 保留 |
| stage1_start | BE -> FE | Stage1 开始 | 保留 |
| thinking | BE -> FE | 每次 emit_thinking | 扩展字段 |
| stage1_answer_delta | BE -> FE | Stage1 回答流式片段 | 新增 |
| stage1_answer_done | BE -> FE | 单议员回答完成 | 新增 |
| stage1_item | BE -> FE | 单议员 Stage1 结果落定 | 保留 |
| stage1_complete | BE -> FE | Stage1 全部完成 | 保留 |
| stage2_start | BE -> FE | Stage2 开始 | 保留 |
| stage2_item | BE -> FE | 评审结果逐条返回 | 保留 |
| stage2_complete | BE -> FE | Stage2 完成 | 保留 |
| stage3_start | BE -> FE | Stage3 开始 | 保留 |
| stage3_complete | BE -> FE | Stage3 完成 | 保留 |
| title_complete | BE -> FE | 首条消息标题生成 | 保留 |
| complete | BE -> FE | 全流程完成 | 保留 |
| error | BE -> FE | 流式错误 | 保留 |

#### 3.1.2 thinking 事件字段定义

```json
{
  "type": "thinking",
  "stage": "stage1",
  "councilor_id": "immanuel_kant",
  "model": "openai/gpt-oss-20b:free",
  "bullet_id": "b1",
  "title": "分析问题核心",
  "detail": "梳理需求边界并确认目标条件",
  "op": "append",
  "t": 1.23
}
```

**字段说明：**

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| type | string | 是 | 固定为 `thinking` |
| stage | string | 是 | `stage1` 固定 |
| councilor_id | string | 是 | 议员 ID |
| model | string | 否 | 议员实际模型名 |
| bullet_id | string | 是 | 思考步骤唯一 ID |
| title | string | 是 | 思考步骤标题（短语） |
| detail | string | 否 | 思考步骤细节（1-3 行） |
| op | string | 是 | `append` 或 `update` |
| t | number | 是 | 相对起始时间（秒） |

#### 3.1.3 stage1_answer_delta 事件字段定义

```json
{
  "type": "stage1_answer_delta",
  "councilor_id": "immanuel_kant",
  "delta": "根据你的问题，我建议..."
}
```

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| type | string | 是 | 固定为 `stage1_answer_delta` |
| councilor_id | string | 是 | 对应议员 |
| delta | string | 是 | 流式文本片段 |

#### 3.1.4 stage1_answer_done 事件字段定义

```json
{
  "type": "stage1_answer_done",
  "councilor_id": "immanuel_kant"
}
```

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| type | string | 是 | 固定为 `stage1_answer_done` |
| councilor_id | string | 是 | 对应议员 |

#### 3.1.5 事件顺序约束（无歧义）

- `thinking` 可能先于 `stage1_answer_delta` 出现。
- `thinking` 与 `stage1_answer_delta` 交错出现（允许并发）。
- `stage1_answer_done` 必须在该议员最后一个 `stage1_answer_delta` 之后。
- `stage1_complete` 只有在所有议员 `stage1_answer_done` 之后发送。

### 3.2 Thinking 数据结构与合并规则

#### 3.2.1 前端 in-memory 结构

```js
thinkingByCouncilor = {
  [councilor_id]: {
    status: "thinking|done|error",
    steps: [
      { bullet_id, title, detail, t }
    ]
  }
}
```

#### 3.2.2 合并规则（apply op）

| op | 行为 | 规则 |
|---|---|---|
| append | 新增步骤 | 直接 push 到 steps 末尾 |
| update | 更新步骤 | 在 steps 中按 bullet_id 查找并覆盖 title/detail |

**冲突处理：**
- 若 update 找不到 bullet_id，则视为 append。
- 若 title 或 detail 为空，不覆盖已有值。

#### 3.2.3 持久化结构（metadata.thinking）

```json
"metadata": {
  "thinking": {
    "version": "thinking_v2",
    "stage1": {
      "<councilor_id>": {
        "model": "...",
        "status": "thinking|done|error",
        "steps": [
          {"bullet_id": "b1", "title": "...", "detail": "...", "t": 1.23}
        ]
      }
    },
    "stage2": {},
    "stage3": {}
  }
}
```

**说明：**
- 写入时只保存合并后的最终 steps。
- 保留每议员最大 50 steps，总计 200 steps 限制。

### 3.3 Stage1/Stage2 文本与提示词约束

#### 3.3.1 Stage1 Prompt 约束（参考 demo）

| 约束 | 说明 |

| EX-005 | SSE 中断 | 网络断线 | 保留已显示内容；刷新后回放 |
| EX-006 | 流式大量空白 | delta 空白过多 | 前端跳过空白片段 |
| EX-007 | 议员失败 | stage1_item status=failed | 显示失败状态，无 thinking |
| EX-008 | 模型不支持 thinking | capability false | 不显示思考区 |
| EX-009 | metadata.thinking 缺失 | 历史数据没有 metadata | 不报错，思考区空 |
| EX-010 | 过量 thinking | 超过上限 | 丢弃超出部分 |

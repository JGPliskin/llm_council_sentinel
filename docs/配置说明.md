# 系统配置说明（Configuration Guide）

本文件为当前项目的配置与运行参数说明，覆盖所有可配置项、默认值与影响范围。目标是“给任何人看，都没有歧义”。

---

## 1. 配置文件总览

| 文件 | 作用 |
|---|---|
| `backend/config.py` | 后端核心配置（模型池、角色、超时、健康参数） |
| `backend/main.py` | 路由、限流常量、API 输入限制 |
| `frontend/src/api.js` | 前端 API 基础地址与请求封装 |

---

## 2. 基础与 API 配置（`backend/config.py`）

| 配置项 | 说明 | 默认值/示例 | 影响 |
|---|---|---|---|
| `OPENROUTER_API_KEY` | OpenRouter API Key | `sk-or-v1-...` | 为空时无法请求模型 |
| `OPENROUTER_API_URL` | OpenRouter API Endpoint | `https://openrouter.ai/api/v1/chat/completions` | 所有模型请求的目的地 |
| `ADMIN_TOKEN` | 管理接口 Token | `secret-token` | 删除/批量删除接口的认证 |
| `DATA_DIR` | 会话文件存储目录 | `data/conversations` | 会话 JSON 存储位置 |

## 3. 模型池与角色配置（`backend/config.py`）

系统采用 **两级模型配置**：首先定义“全局模型池”，然后在“Councilor”中引用模型或候选列表。

### 3.1 全局模型池 (`GLOBAL_MODEL_POOL`)

定义所有可用模型的元数据。

字段结构：
- `id`: 模型唯一标识（OpenRouter ID）
- `name`: 人类可读名称
- `concurrency_limit`: 该模型的最大并发请求数（控制 semaphore）
- `category`: 分类（general, reasoning, fast, research）
- `capabilities`: 能力标记
  - `thinking`: 是否支持显示思维链 (CoT)
  - `mode`: 工作模式 (通常为 "tool" 或 "chat")

示例：
```python
GLOBAL_MODEL_POOL = [
    {
        "id": "xiaomi/mimo-v2-flash:free",
        "name": "Mimo V2 Flash (Free)",
        "concurrency_limit": 5,
        "category": "fast",
        "capabilities": {"thinking": True, "mode": "standard"},
    },
    {
        "id": "nvidia/nemotron-nano-9b-v2:free",
        "name": "Nemotron Nano 9B V2 (Free)",
        "concurrency_limit": 5,
        "category": "fast",
        "capabilities": {"thinking": True, "mode": "tool"},
    },
    # ... 更多模型
]
```

### 3.2 Councilor 列表 (`COUNCILORS`)

定义参与 Stage1 和 Stage2 的角色。

字段结构：
- `id`: 唯一 ID（用于前端与存储）
- `name`: 展示名称
- `model`: **默认首选模型 ID**
- `model_candidates`: **候选模型列表**（按优先级排序）。当默认模型健康检查失败时，会自动回退到候选列表中的第一个健康模型。
- `avatar`: 前端展示的 Emoji 或图标
- `persona_path`: Stage1 人设文件路径
- `judge_persona_path`: Stage2 评审人设文件路径
- `judge_system_prompt`: Stage2 核心评审指令
- `stage_limits`: 阶段级超时与 token 限制（覆盖默认值）

示例结构：
```python
COUNCILORS = [
    {
        "id": "immanuel_kant",
        "name": "康德",
        "model": "xiaomi/mimo-v2-flash:free",
        "model_candidates": [
            "xiaomi/mimo-v2-flash:free",
            "nvidia/nemotron-nano-9b-v2:free",
            "nvidia/nemotron-3-nano-30b-a3b:free",
            "nvidia/nemotron-nano-12b-v2-vl:free",
            "tngtech/tng-r1t-chimera:free",
        ],
        "avatar": "🧠",
        "persona_path": "backend/personas/immanuel_kant.md",
        "judge_persona_path": "backend/personas/immanuel_kant_judge.md",
        "judge_system_prompt": "...",
        "stage_limits": {
            "stage1": {"max_output_tokens": 800, "timeout": 120.0},
            "stage2": {"max_output_tokens": 360, "timeout": 75.0}
        },
    },
    # 更多 Councilors: donald_trump (🧱), hideo_kojima (🎮)
]
```

### 3.3 Chairman 定义 (`CHAIRMAN`)

## 4. 并发与超时（`backend/config.py`）

| 配置项 | 说明 | 示例 | 影响 |
|---|---|---|---|
| `DEFAULT_CONCURRENCY_STAGE1` | Stage1 协程并发数 | `6` | 控制同时发起的 Stage1 请求数 |
| `DEFAULT_CONCURRENCY_STAGE2` | Stage2 协程并发数 | `4` | 控制同时发起的 Stage2 评审数 |
| `DEFAULT_STAGE1_TIMEOUT` | Stage1 默认单次超时 | `120.0` | 单个请求超时 |
| `DEFAULT_STAGE2_TIMEOUT` | Stage2 默认单次超时 | `180.0` | 单个请求超时 |
| `STAGE1_DEADLINE` | Stage1 总截止时间 | `None` | 整个 Stage1 阶段的硬性 deadline (None表示禁用) | 
| `STAGE2_DEADLINE` | Stage2 总截止时间 | `None` | 整个 Stage2 阶段的硬性 deadline |

## 5. 健康检查与重试（`backend/config.py` / `backend/health.py`）

**核心机制**：
1. **健康状态**：模型状态分为 `healthy`, `degraded`, `unhealthy`, `unknown`。
2. **硬失败 (Hard Failure)**：特定错误码直接标记模型为不可用，不进行重试。
3. **软失败与冷却**：常规超时或 500 错误会增加失败计数，达到阈值后进入冷却 (Backoff)。

### 5.1 参数配置

| 配置项 | 说明 | 示例 |
|---|---|---|
| `FAILURE_THRESHOLD` | 连续失败阈值 | `2` |
| `BACKOFF_SECONDS` | 冷却退避秒数列表 | `[120, 300, 900, 3600]` |
| `HEALTH_TTL_SECONDS` | 健康缓存 TTL | `3600` |
| `REFRESH_COOLDOWN_SECONDS` | 手动刷新冷却 | `60` |
| `HEALTH_STARTUP_CHECK` | 启动时是否立即探测 | `False` (默认被动) |
| `PROBE_TIMEOUT_SECONDS` | 探测请求超时 | `25.0` |
| `HEALTH_PROBE_CONCURRENCY` | 探测并发数 | `4` |
| `HEALTH_CHECK_START_HOUR` | 检查开始时间 (Hour) | `10` | 健康检查只在此时间后进行 |
| `HEALTH_CHECK_END_HOUR` | 检查结束时间 (Hour) | `24` | 健康检查只在此时间前进行 |
| `HEALTH_CHECK_INTERVAL` | 检查间隔 (Seconds) | `7200` | 定时任务唤醒间隔 |
| `HEALTH_CHECK_TIMEZONE` | 时区 | `Asia/Shanghai` | 时段控制基准时区 |

### 5.2 硬失败规则
当 OpenRouter 返回以下错误时，模型立即被标记为 unhealthy：
- **Codes**: `401` (Unauthorized), `403` (Forbidden), `404` (Not Found)
- **Error Patterns**: 
  - "does not exist"
  - "not found"
  - "permission denied"
  - "unauthorized"
  - \"disabled\"

### 5.3 速度自动选路 (Stage1)

系统支持根据模型 TTFT（首字延迟）自动选择最快的模型。

**Councilor 配置项：**

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `auto_route_by_speed` | `boolean` | `true` | 是否启用速度自动选路 |

**全局阈值配置：**

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `SPEED_ROUTE_SWITCH_ABS_MS` | `800` | 切换绝对阈值 (ms) |
| `SPEED_ROUTE_SWITCH_REL_PCT` | `0.30` | 切换相对阈值 (30%) |
| `EMERGENCY_PROBE_TTFT_THRESHOLD` | `5000` | 紧急探测触发阈值 (ms) |
| `EMERGENCY_PROBE_TTFT_MULTIPLIER` | `3` | 紧急探测触发: TTFT >= EMA × 此值 |
| `EMERGENCY_PROBE_COOLDOWN_MINUTES` | `10` | 紧急探测冷却 (分钟，per-model) |

**切换规则**：只有同时满足"绝对差 >= 800ms"且"相对差 >= 30%"时，才会从当前模型切换到更快的模型。

## 6. 限流与输入限制（`backend/main.py`）

| 配置项 | 说明 | 默认值 |
|---|---|---|
| `MAX_MESSAGE_LENGTH` | 最大消息长度 | `1000` |
| `RATE_LIMIT_MESSAGE` | POST /message 限流 | `5/minute` |
| `RATE_LIMIT_STREAM` | POST /stream 限流 | `5/minute` |

**限流来源**：使用 `slowapi`，基于真实 IP（支持 X-Forwarded-For / X-Real-IP）。

---

## 8. 修改配置标准步骤

1. **修改 `backend/config.py`**：调整模型 ID、Prompt、超时参数。
   - 注意：修改 Prompt 建议直接修改 `backend/personas/` 下对应的 `.md` 文件。
2. **重启后端**：配置即时生效需要重启 FastAPI 服务。
3. **前端影响**：如果是修改了 `avatar` 或 `name`，前端会在下次请求 `/api/councilors` 时自动获取更新（无需重新构建前端）。

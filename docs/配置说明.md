# 系统配置说明（Configuration Guide）

本文件为当前项目的配置与运行参数说明，覆盖所有可配置项、默认值与影响范围。内容以 `backend/config.py` 与 `backend/main.py` 为准。

---

## 1. 配置文件总览

| 文件 | 作用 |
|---|---|
| `backend/config.py` | 后端核心配置（模型池、角色、超时、健康参数） |
| `backend/main.py` | 限流与输入限制 |
| `frontend/src/api.js` | 前端 API Base 配置 |

---

## 2. 基础配置（`backend/config.py`）

| 配置项 | 说明 | 默认值 |
|---|---|---|
| `OPENROUTER_API_KEY` | OpenRouter API Key | 环境变量 `OPENROUTER_API_KEY` |
| `OPENROUTER_API_URL` | OpenRouter API Endpoint | `https://openrouter.ai/api/v1/chat/completions` |
| `ADMIN_TOKEN` | 管理接口 Token | 环境变量 `ADMIN_TOKEN`，默认 `secret-token` |
| `DATA_DIR` | 对话存储目录 | `data/conversations` |

### 2.1 NIM 配置 (新增)

| 配置项 | 说明 | 默认值 |
|---|---|---|
| `NIM_API_KEYS` | Nvidia NIM API Keys (逗号分隔支持多个) | 环境变量 `NIM_API_KEYS` |
| `NIM_API_BASE` | NIM API Endpoint | `https://integrate.api.nvidia.com/v1` |
| `NIM_RPM_PER_KEY` | 每个 Key 的 RPM 限制 | `40` |

## 3. 模型池与角色配置

### 3.1 全局模型池（`GLOBAL_MODEL_POOL`）

字段结构：
- `id`：模型唯一标识（OpenRouter ID）
- `name`：可读名称
- `concurrency_limit`：该模型并发上限
- `category`：分类（fast / reasoning）
- `capabilities.thinking`：是否支持 Thinking 工具
- `category`：分类（fast / reasoning）
- `capabilities.thinking`：是否支持 Thinking 工具
- `capabilities.mode`：`standard` / `tool`
- `provider`：`openrouter` / `nim` (标识供应商路由)

### 3.1.1 总结模型池 (`SUMMARY_MODEL_CANDIDATES`)
用于生成会话标题的专用候选池（自动选路）：
- `openrouter:xiaomi/mimo-v2-flash:free`
- `openrouter:mistralai/devstral-2512:free`
- `openrouter:z-ai/glm-4.5-air:free`
- `openrouter:qwen/qwen3-coder:free`

### 3.2 Councilor 配置（`COUNCILORS`）

每位 Councilor 字段：
- `id` / `name` / `avatar`
- `model`：默认模型 ID
- `model_candidates`：候选池
- `persona_path`：Stage1 Persona
- `judge_persona_path`：Stage2 Persona
- `judge_system_prompt`：Stage2 系统提示
- `stage_limits.stage1` / `stage_limits.stage2`

### 3.3 Chairman 配置（`CHAIRMAN`）

- `stage_limits.stage3` 控制主席生成超时与 token 限制

## 4. 并发与超时

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `DEFAULT_CONCURRENCY_STAGE1` | `6` | Stage1 并发 |
| `DEFAULT_CONCURRENCY_STAGE2` | `4` | Stage2 并发 |
| `DEFAULT_STAGE1_TIMEOUT` | `120.0` | Stage1 默认超时 |
| `DEFAULT_STAGE2_TIMEOUT` | `180.0` | Stage2 默认超时 |
| `STAGE1_DEADLINE` | `180.0` | Stage1 整体 deadline |
| `STAGE2_DEADLINE` | `180.0` | Stage2 整体 deadline |

实际 Stage2 超时由 `COUNCILORS[].stage_limits.stage2.timeout` 覆盖（默认 75s）。

---

## 5. ETA 预估默认值

用于冷启动阶段的 ETA 兜底（运行时 EMA 样本不足时启用）。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `DEFAULT_ETA_CONFIG.default_ttft_ms` | `2000` | 默认首 token 时间 (ms) |
| `DEFAULT_ETA_CONFIG.default_generation_ms` | `5000` | 默认生成时间 (ms) |
| `DEFAULT_ETA_CONFIG.default_queue_wait_ms` | `1000` | 默认队列等待 (ms) |
| `DEFAULT_ETA_CONFIG.warmup_sample_count` | `3` | EMA 启动所需最小样本数 |

---

## 6. 健康检查与路由

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `HEALTH_TTL_SECONDS` | `3600` | 健康缓存 TTL |
| `REFRESH_COOLDOWN_SECONDS` | `60` | 刷新冷却 |
| `FAILURE_THRESHOLD` | `2` | 连续失败阈值 |
| `BACKOFF_SECONDS` | `[120, 300, 900, 3600]` | 冷却时间梯度 |
| `PROBE_TIMEOUT_SECONDS` | `25.0` | 探测超时 |
| `HEALTH_PROBE_CONCURRENCY` | `4` | 探测并发 |
| `HEALTH_STARTUP_CHECK` | `False` | 启动时是否探测 |
| `HEALTH_CHECK_START_HOUR` | `10` | 定时健康检查开始小时 |
| `HEALTH_CHECK_END_HOUR` | `24` | 定时健康检查结束小时 |
| `HEALTH_CHECK_INTERVAL` | `7200` | 定时健康检查间隔（秒） |
| `HEALTH_CHECK_TIMEZONE` | `Asia/Shanghai` | 时区 |

**硬失败规则**：
- HTTP 401 / 403 / 404
- Error message 匹配：`does not exist` / `not found` / `permission denied` / `unauthorized` / `disabled`

## 7. 速度自动选路（Stage1）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `SPEED_ROUTE_SWITCH_ABS_MS` | `800` | 切换绝对阈值 (ms) |
| `SPEED_ROUTE_SWITCH_REL_PCT` | `0.30` | 切换相对阈值 |
| `EMERGENCY_PROBE_TTFT_THRESHOLD` | `20000` | 紧急探测 TTFT 阈值 (ms) |
| `EMERGENCY_PROBE_TTFT_MULTIPLIER` | `3` | TTFT >= EMA * multiplier 触发 |
| `EMERGENCY_PROBE_COOLDOWN_MINUTES` | `30` | 紧急探测冷却 |

# 系统配置说明文档 (System Configuration Guide)

本文档整理了当前系统中的关键配置项，涵盖基础设置、模型参数、并发控制、重试机制及提示词（Prompt）配置。

## 1. 基础与API配置
**文件路径**: `backend/config.py`

| 配置项 | 说明 | 影响 | 示例 |
| :--- | :--- | :--- | :--- |
| `OPENROUTER_API_KEY` | OpenRouter API 密钥 | 用于鉴权。未配置会导致无法请求模型。 | `sk-or-v1-...` |
| `OPENROUTER_API_URL` | API 接口地址 | 决定请求发送的目标 URL。 | `https://openrouter.ai/api/v1/chat/completions` |
| `ADMIN_TOKEN` | 管理员 Token | 用于保护敏感接口（如刷新 Config）。前端需在 Header 中携带此 Token。 | `secret-token` |
| `DATA_DIR` | 数据存储目录 | 对话历史 JSON 文件的保存位置。 | `data/conversations` |

## 2. 并发与超时 (Concurrency & Timeouts)
**文件路径**: `backend/config.py`

| 配置项 | 说明 | 影响 | 示例 |
| :--- | :--- | :--- | :--- |
| `DEFAULT_CONCURRENCY_STAGE1` | 第一阶段并发数 | 限制同时请求 Answer 模型的数量。过高可能触及 Rate Limit，过低影响速度。 | `6` |
| `DEFAULT_CONCURRENCY_STAGE2` | 第二阶段并发数 | 限制同时请求 Judge 模型的数量。 | `4` |
| `DEFAULT_STAGE1_TIMEOUT` | 第一阶段单次超时(秒) | 单个模型生成回答的最大等待时间。 | `120.0` |
| `DEFAULT_STAGE2_TIMEOUT` | 第二阶段单次超时(秒) | 单个模型进行评分的最大等待时间。 | `180.0` |
| `STAGE1_DEADLINE` | 第一阶段总截止时间 | 整个第一阶段的最长耗时。`None` 表示不限制。开启后若超时会强制取消剩余任务。 | `None` 或 `180.0` |

## 3. 重试与健康检查 (Retry & Health)
**文件路径**: `backend/config.py` (配置参数) 和 `backend/council.py` (逻辑实现)

| 配置项 | 位置 | 说明 | 影响 | 示例 |
| :--- | :--- | :--- | :--- | :--- |
| `attempts` (Hardcoded) | `backend/council.py` | 每个请求的最大尝试次数。当前固定为 2 (1次初试 + 1次重试)。 | 决定网络抖动或 JSON 解析失败时的容错率。 | 代码中 `for attempt in range(2):` |
| `FAILURE_THRESHOLD` | `backend/config.py` | 连续失败次数阈值。 | 超过此次数，模型会被标记为不健康。 | `2` |
| `BACKOFF_SECONDS` | `backend/config.py` | 健康检查避退时间阶梯。 | 模型被标记不健康后的重试等待时间。 | `[120, 300, 900, 3600]` |
| `HEALTH_TTL_SECONDS` | `backend/config.py` | 健康状态缓存有效期。 | 多久后视为过期需重新检测。 | `3600` (1小时) |

> **注意**: 在 `backend/council.py` 中，如果API返回 `Retry-After` Header，系统会优先遵循，否则使用随机延时 `0.8~2.0` 秒。

## 4. 议员与模型配置 (Councilors)
**文件路径**: `backend/config.py` (定义)

在 `COUNCILORS` 列表中配置每个议员的具体参数：

| 参数 | 说明 | 影响 | 示例 |
| :--- | :--- | :--- | :--- |
| `model` | 模型 ID | 指定该议员调用的底层大模型。 | `meituan/longcat-flash-chat:free` |
| `persona_path` | 人设文件路径 | 指向 `backend/personas/*.md`，定义议员的回答风格。 | `backend/personas/hefei_strategist.md` |
| `judge_system_prompt` | 评审 System Prompt | **直接写在 py 文件中**的字符串。定义该议员在第二阶段点评时的具体要求。 | `"保持冷静的政策分析腔调..."` |
| `stage_limits` | 阶段限制 | 覆盖默认的超时和 Token 限制。 | `{"retry": {"max_output_tokens": 800}}` |

## 5. 提示词 (Prompts)
提示词分散在配置文件和代码逻辑中：

### A. 人设提示词 (Personas)
**位置**: `backend/personas/` 文件夹下的 `.md` 文件。
**用途**: 第一阶段 (Stage 1) 回答问题时，作为系统提示词的基础部分。
**示例**: `backend/personas/hefei_strategist.md`

### B. 系统指令 (System Instructions)
**位置**: `backend/council.py` -> `_request_stage1_bounded` 函数
**内容**: 代码中硬编码的格式要求（"严格遵守..."），强制规定返回 JSON 格式、字段约束、字数限制。
**修改方式**: 需修改 `backend/council.py` 源码。

### C. 评审与排名指令 (Judge & Ranking)
**位置**: `backend/council.py` -> `_build_ranking_messages` 函数
**内容**: 指导模型如何输出 JSON 格式的排名结果（`ranking`, `scores`, `rationale`）。
**修改方式**: 需修改 `backend/council.py` 源码。

---
**如何修改配置？**
1. **简单参数**: 直接修改 `backend/config.py` 中的变量值。
2. **人设内容**: 编辑 `backend/personas/` 下对应的 Markdown 文件。
3. **复杂逻辑/Prompt结构**: 需要谨慎修改 `backend/council.py` 中的代码块。

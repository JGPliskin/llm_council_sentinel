# 系统配置说明文档 (System Configuration Guide)

本文档整理了当前系统中的关键配置项，涵盖基础设置、模型参数、并发控制、重试机制及提示词（Prompt）配置。

## 1. 基础与API配置
**文件路径**: `backend/config.py`

| 配置项 | 说明 | 影响 | 示例 |
| :--- | :--- | :--- | :--- |
| `OPENROUTER_API_KEY` | OpenRouter API 密钥 | 用于鉴权。未配置会导致无法请求模型。 | `sk-or-v1-...` |
| `OPENROUTER_API_URL` | API 接口地址 | 决定请求发送的目标 URL。 | `https://openrouter.ai/api/v1/chat/completions` |
| `ADMIN_TOKEN` | 管理员 Token | 用于保护敏感接口（如刷新 Config）。前端需在 Header 中携带此 Token。 | `secret-token` |
| `DATA_DIR` | 数据存储目录 | 对话历史 JSON 文件的保存位置。 | `data/conversations` |

## 2. 并发与超时 (Concurrency & Timeouts)
**文件路径**: `backend/config.py`

| 配置项 | 说明 | 影响 | 示例 |
| :--- | :--- | :--- | :--- |
| `DEFAULT_CONCURRENCY_STAGE1` | 第一阶段并发数 | 限制同时请求 Answer 模型的数量。过高可能触及 Rate Limit，过低影响速度。 | `6` |
| `DEFAULT_CONCURRENCY_STAGE2` | 第二阶段并发数 | 限制同时请求 Judge 模型的数量。 | `4` |
| `DEFAULT_STAGE1_TIMEOUT` | 第一阶段单次超时(秒) | 单个模型生成回答的最大等待时间。 | `120.0` |
| `DEFAULT_STAGE2_TIMEOUT` | 第二阶段单次超时(秒) | 单个模型进行评分的最大等待时间。 | `180.0` |
| `STAGE1_DEADLINE` | 第一阶段总截止时间 | 整个第一阶段的最长耗时。`None` 表示不限制。开启后若超时会强制取消剩余任务。 | `None` 或 `180.0` |
| `STAGE2_DEADLINE` | 第二阶段总截止时间 | 超时会取消未完成的评审任务并返回 `STAGE_DEADLINE` 错误。 | `None` 或自定义秒数 |

## 3. 重试与健康检查 (Retry & Health)
**文件路径**: `backend/config.py` (配置参数) 和 `backend/council.py` (逻辑实现)

| 配置项 | 位置 | 说明 | 影响 | 示例 |
| :--- | :--- | :--- | :--- | :--- |
| `attempts` (Hardcoded) | `backend/council.py` | 每个请求的最大尝试次数。当前固定为 2 (1次初试 + 1次重试)。 | 决定网络抖动或 JSON 解析失败时的容错率。 | 代码中 `for attempt in range(2):` |
| `FAILURE_THRESHOLD` | `backend/config.py` | 连续失败次数阈值。 | 超过此次数，模型会被标记为不健康。 | `2` |
| `BACKOFF_SECONDS` | `backend/config.py` | 健康检查避退时间阶梯。 | 模型被标记不健康后的重试等待时间。 | `[120, 300, 900, 3600]` |
| `HEALTH_TTL_SECONDS` | `backend/config.py` | 健康状态缓存有效期。 | 多久后视为过期需重新检测。 | `3600` (1小时) |
| `REFRESH_COOLDOWN_SECONDS` | `backend/config.py` | 刷新冷却时间 | 避免过于频繁的手动刷新请求。 | `60` |
| `HEALTH_STARTUP_CHECK` | `backend/config.py` | 启动时健康检查 | 是否在应用启动时立即探测所有模型。 | `False` |
| `PROBE_TIMEOUT_SECONDS` | `backend/config.py` | 探测超时 | 健康检查请求的特定超时时间。 | `25.0` |
| `HEALTH_PROBE_CONCURRENCY` | `backend/config.py` | 探测并发度 | 健康探测阶段的并发上限，避免压垮上游 API。 | `4` |

> **注意**: 
> 1. 系统定义了 `HARD_FAILURE_CODES` (401, 403, 404) 和 `HARD_FAILURE_PATTERNS` (如 'permission denied')，遇到这些错误直接判定为不健康，不进行重试。
> 2. 如果API返回 `Retry-After` Header，系统会优先遵循，否则使用随机延时 `0.8~2.0` 秒。

## 4. 议员与模型配置 (Councilors)
**文件路径**: `backend/config.py` (定义)

在 `COUNCILORS` 列表中配置每个议员的具体参数：

| 参数 | 说明 | 影响 | 示例 |
| :--- | :--- | :--- | :--- |
| `model` | 模型 ID | 指定该议员调用的底层大模型。 | `openai/gpt-oss-20b:free` |
| `persona_path` | 人设文件路径 | 指向 `backend/personas/*.md`，定义议员的回答风格。 | `backend/personas/immanuel_kant.md` |
| `judge_system_prompt` | 评审 System Prompt | **直接写在 py 文件中**的字符串。定义该议员在第二阶段点评时的具体要求。 | `"保持冷静的政策分析腔调..."` |
| `stage_limits` | 阶段限制 | 覆盖默认的超时和 Token 限制。 | `{"stage1": {"max_output_tokens": 800}}` |

## 5. 提示词 (Prompts)
提示词分散在配置文件和代码逻辑中：

### A. 人设提示词 (Personas)
**位置**: `backend/personas/` 文件夹下的 `.md` 文件。
**用途**: 第一阶段 (Stage 1) 回答问题时，作为系统提示词的基础部分。
**示例**: `backend/personas/immanuel_kant.md`

### B. 系统指令 (System Instructions)
**位置**: `backend/council.py` -> `_request_stage1_bounded` 函数
**内容**: 代码中硬编码的格式要求（"严格遵守..."），强制规定返回 JSON 格式、字段约束、字数限制。
**修改方式**: 需修改 `backend/council.py` 源码。

### C. 评审与排名指令 (Judge & Ranking)
**位置**: `backend/council.py` -> `_build_ranking_messages` 函数
**内容**: 指导模型如何输出 JSON 格式的排名结果（`ranking`, `scores`, `rationale`）。
**修改方式**: 需修改 `backend/council.py` 源码。

## 6. 阶段限制（按人设）
**文件路径**: `backend/config.py`

- **康德 / 特朗普 / 小岛秀夫（Stage 1）**：`max_output_tokens` 800~820，超时时间使用 `DEFAULT_STAGE1_TIMEOUT`。  
- **三位议员（Stage 2）**：`max_output_tokens` 360，超时时间 75s（覆盖默认）。  
- **主席（Stage 3）**：`max_output_tokens` 900，超时时间 90s。  

## 7. 运行时限制与配额
**文件路径**: `backend/main.py`

- **消息长度**：`MAX_MESSAGE_LENGTH = 1000`，空内容或超长会抛出结构化错误码（`CONTENT_TOO_LONG` / `VALIDATION_ERROR`）。  
- **频控**：`/api/conversations/{id}/message` 与 `/api/conversations/{id}/message/stream` 均限制为 `5/min`，基于 SlowAPI，按 `X-Forwarded-For` 首个 IP 计数。  
- **CORS**：允许 `localhost:5173/3000/80` 等本地和 Docker Nginx 源。  
- **Admin Token**：当前 `verify_admin` 默认放行（返回 debug token），如需保护删除接口需手动恢复校验。  

## 8. 会话存储与迁移
**文件路径**: `backend/storage.py`

- 会话持久化：写入 `data/conversations/{id}.json`，Schema v2 字段包含 `id/created_at/title/messages/active_councilor_ids/active_chairman/schema_version`。  
- 删除：单个删除会校验 ID 格式（`[A-Za-z0-9_-]{1,64}`），批量删除会去重并标记 `invalid_id`、`permission_denied`、`file_locked` 等原因。  
- 迁移：旧版 `active_models` 会在写入消息时迁移到 `active_councilor_ids`（v2），首次迁移会生成 `.bak` 备份。  

## 9. 标题生成与模型选择
**文件路径**: `backend/council.py`

- 首条用户消息会异步调用 `kwaipilot/kat-coder-pro:free` 生成 3-5 词标题，超时 30 秒，长度超过 50 字符会被截断；失败则回退到 `"New Conversation"`。  

---
**如何修改配置？**
1. **简单参数**: 直接修改 `backend/config.py` 中的变量值。
2. **人设内容**: 编辑 `backend/personas/` 下对应的 Markdown 文件。
3. **复杂逻辑/Prompt结构**: 需要谨慎修改 `backend/council.py` 中的代码块。

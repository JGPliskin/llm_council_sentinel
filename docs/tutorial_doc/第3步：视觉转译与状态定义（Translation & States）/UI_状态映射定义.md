# 🚦 UI 状态映射定义：LLM Council Sentinel Stage 1 & Stage 2

## 1. 组件概述
* **组件名称**：StageContainer (Stage 容器) / AnswerArea (回答区域) / ThinkingPanel (思考面板) / EvaluationPanel (评价面板) / HUDProgress (HUD 进度条)
* **复用场景**：Stage 1 (议员思考与回答) & Stage 2 (议员评价与排名)
* **核心逻辑**：选项卡切换 + 响应式布局（PC 左右/移动端上下）+ 面板开关控制

## 2. 全局交互规范
* **选项卡切换**：点击议员选项卡时，左侧回答区域和右侧面板内容同步切换
* **面板开关**：右侧/下方面板可以打开/关闭，关闭后只显示左侧/上方回答区域
* **响应式布局**：PC 端左右布局，移动端上下布局
* **自动滚动**：生成过程中，回答区域自动滚动到底部
* **Markdown 渲染**：代码块、表格、公式实时渲染，防止高度抖动
* **打字机效果**：不开启流式打字机效果，直接显示完整文本

## 3. 状态详细映射表

### 3.1 StageContainer (Stage 容器)

| 状态 | 视觉表现 (Visual) | 交互行为 (Interaction) | 文案/提示 (Copy) | 备注 (逻辑) |
| :--- | :--- | :--- | :--- | :--- |
| **0. 初始空态 (Empty)** | 选项卡区域显示，但回答区域和面板区域隐藏或显示占位符 | 不可交互 | - | 还没开始问时的状态 |
| **1. 思考中 (Thinking)** | 选项卡显示，回答区域显示"正在思考..."，思考面板显示思考过程 | 选项卡可切换，面板可开关 | "正在思考..." | Stage 1 专用状态 |
| **2. 生成中 (Streaming)** | 选项卡显示，回答区域直接显示完整文本（无打字机效果），思考面板继续更新 | 选项卡可切换，面板可开关 | (完整文本) | Stage 1 专用状态 |
| **3. 理想完成态 (Ideal)** | 选项卡显示，回答区域完整显示，思考面板/评价面板显示完整内容 | 选项卡可切换，面板可开关 | (完整文本) | Stage 1 显示思考面板，Stage 2 显示评价面板 |
| **4. 报错/失败 (Error)** | 选项卡显示，回答区域显示错误信息 | 选项卡可切换 | 「网络请求失败」 或 「模型被内容拦截」 | 无重试按钮，用户需重新提问 |

### 3.2 AnswerArea (回答区域)

| 状态 | 视觉表现 (Visual) | 交互行为 (Interaction) | 文案/提示 (Copy) | 备注 (逻辑) |
| :--- | :--- | :--- | :--- | :--- |
| **0. 初始空态 (Empty)** | 区域隐藏或显示淡色占位符（如：Logo 水印） | 不可交互 | - | 还没开始问时的状态 |
| **1. 思考中 (Thinking)** | 显示"正在思考..."或加载动画，背景可能有呼吸灯效果 | 不可交互 | "正在思考..." | 对应 API 建立连接前的等待期 (TTFT) |
| **2. 生成中 (Streaming)** | 直接显示完整文本（无打字机效果），Markdown 格式完全渲染 | 不可交互 | (完整文本) | 无流式效果，一次性显示 |
| **3. 理想完成态 (Ideal)** | Markdown 完全渲染（代码高亮） | 不可交互（无复制按钮） | (完整文本) | Stage 1 和 Stage 2 内容相同，固定不变 |
| **4. 报错/失败 (Error)** | 文本红色或灰色，显示明显的错误图标 | 无按钮，用户需重新提问 | 「网络请求失败」 或 「模型被内容拦截」 | 无重试按钮 |
| **5. 文本截断/过长 (Truncated)** | 底部显示渐变遮罩 + "展开全文"按钮 | 点击展开完整内容 | "展开全文" | 防止单条回答太长占满屏幕 |

### 3.3 ThinkingPanel (思考面板 - Stage 1 专用)

| 状态 | 视觉表现 (Visual) | 交互行为 (Interaction) | 文案/提示 (Copy) | 备注 (逻辑) |
| :--- | :--- | :--- | :--- | :--- |
| **0. 面板关闭 (Closed)** | 面板隐藏，只显示回答区域 | 点击"打开思考"按钮显示面板 | - | 用户可以关闭面板 |
| **1. 思考中 (Thinking)** | 显示"思考中..."，下方显示实时思考步骤（如"分析问题..."、"收集信息..."） | 可关闭面板 | "思考中..." | 实时更新思考步骤 |
| **2. 思考完成 (Completed)** | 显示完整的思考历史时间线，每个步骤带时间戳 | 可关闭面板 | (思考历史) | 思考步骤 + 时间戳（如"+2.3s"） |
| **3. 面板打开 (Opened)** | 面板显示完整内容，带关闭按钮 | 点击关闭按钮隐藏面板 | - | 用户可以打开/关闭面板 |

### 3.4 EvaluationPanel (评价面板 - Stage 2 专用)

| 状态 | 视觉表现 (Visual) | 交互行为 (Interaction) | 文案/提示 (Copy) | 备注 (逻辑) |
| :--- | :--- | :--- | :--- | :--- |
| **0. 面板关闭 (Closed)** | 面板隐藏，只显示回答区域 | 点击"打开评价"按钮显示面板 | - | 用户可以关闭面板 |
| **1. 评价生成中 (Generating)** | 显示"评价生成中..."，下方显示实时更新的评价 | 可关闭面板 | "评价生成中..." | 实时更新评价内容 |
| **2. 评价完成 (Completed)** | 显示完整的评价列表（自评 + 其他议员评价），每个评价独立显示 | 可关闭面板 | (评价列表) | 只显示评价文本，不显示分数 |
| **3. 面板打开 (Opened)** | 面板显示完整内容，带关闭按钮 | 点击关闭按钮隐藏面板 | - | 用户可以打开/关闭面板 |

**默认行为**：评价面板在 Stage 2 完成后 **仅首次自动展开一次**，用户手动关闭后，本次运行不再自动弹出。用户可以通过显式入口再次打开。

### 3.5 HUDProgress (HUD 进度条)

| 状态 | 视觉表现 (Visual) | 交互行为 (Interaction) | 文案/提示 (Copy) | 备注 (逻辑) |
| :--- | :--- | :--- | :--- | :--- |
| **0. 初始空态 (Empty)** | HUD 区域隐藏或显示占位符 | 不可交互 | - | 还没开始问时的状态 |
| **1. Stage 1 生成中 (Stage1 Streaming)** | 显示进度条（如 50%），上方显示"生成中..."，下方显示"2/4 议员完成" | 不可交互 | "生成中..." "2/4 议员完成" | Stage 1 专用，显示议员完成进度 |
| **2. Stage 1 完成 (Stage1 Completed)** | 进度条显示 100%，显示"生成完成" | 不可交互 | "生成完成" | Stage 1 完成，准备进入 Stage 2 |
| **3. Stage 2 评价中 (Stage2 Evaluating)** | 显示进度条（如 75%），上方显示"评价中..."，下方显示"3/4 评价完成" | 不可交互 | "评价中..." "3/4 评价完成" | Stage 2 专用，显示评价完成进度 |
| **4. Stage 2 完成 (Stage2 Completed)** | 进度条显示 100%，下方显示最终排名（从高到低，左侧 rank + 右侧分数） | 不可交互 | "评价完成" + 排名列表 | Stage 2 完成，显示最终排名 |

> **分数展示规则统一说明**：分数仅在 HUD 底部排名区域显示（如 9.2、8.7 等），**评价面板内不重复展示分数**，仅显示评价文本。

### 3.6 Stage3Container (主席总结区域 - Stage 3 专用)

| 状态 | 视觉表现 (Visual) | 交互行为 (Interaction) | 文案/提示 (Copy) | 备注 (逻辑) |
| :--- | :--- | :--- | :--- | :--- |
| **0. 等待中 (Waiting)** | 显示占位文案，背景可加轻微呼吸动效 | 不可交互 | 「主席正在聆听辩论」 | Stage 1/2 未结束时的状态 |
| **1. 生成中 (Streaming)** | 显示生成中的内容（直接显示完整段落，无打字机效果） | 不可交互 | (生成中的内容) | 后端 SSE 推送，前端按段落渲染 |
| **2. 理想完成态 (Ideal)** | 完整 Markdown 渲染 + Chairman 专属背景 + Approved 印章 SVG | 不可交互（无复制按钮） | (完整文本) | 高亮卡片样式，视觉层级最高 |
| **3. 失败/降级 (Fallback)** | 显示降级提示，如有备用模型则显示备用结果 | 不可交互 | 「主席模型失败，已切换至备用」 | 沿用 Stage 1/2 的 fallback 机制 |
| **4. 全部失败 (AllFailed)** | 显示错误信息，背景转为红色/灰色 | 不可交互 | 「无法生成最终结论，请重新提问」 | 主席和备用均失败 |

**Stage 3 位置说明**：Stage 3 位于头像下方、Stage 1 上方，是视觉层级最高的区域。

## 4. 特殊边界情况 (Edge Cases) - **PM 重点关注**

### A. 渲染抖动问题
* **问题**：当模型输出 Markdown 表格或代码块时，正在输入时高度会剧烈跳动。
* **对策**：生成过程中给代码块/表格预设一个最小高度，或者锁定滚动条位置。

### B. 混合内容
* **场景**：回答里既有文本，又有代码，还有 LaTeX 公式。
* **要求**：确保 `$` 符号被正确渲染为公式，而不是美元符号；确保代码块横向滚动条不破坏布局。

### C. Stage 1 vs Stage 2 区分
*虽然组件代码共用，但视觉上建议做区分：*
* **Stage 1 (议员思考)**：建议使用**白色/浅灰底色**，右侧显示思考过程面板。
* **Stage 2 (议员评价)**：建议使用**高亮底色**（如淡黄色、淡蓝色）或加粗边框，右侧显示评价面板。

### D. 响应式布局切换
* **问题**：PC 端左右布局切换到移动端上下布局时，面板开关逻辑需要调整。
* **对策**：PC 端右侧面板关闭时，回答区域自动扩展到全宽；移动端下方面板关闭时，回答区域自动扩展到全高。

### E. 面板开关状态保持
* **问题**：切换选项卡时，面板开关状态是否保持？
* **对策**：建议保持面板开关状态，即如果用户关闭了面板，切换选项卡后面板仍然保持关闭状态。

### E-2. 响应式断点定义
* **问题**：PC 端左右布局切换到移动端上下布局的断点是多少？
* **对策（参考通用设计规范）**：
    * **主断点**：`768px`
        * `>= 768px`：PC 端左右布局（右侧面板）
        * `< 768px`：移动端上下布局（底部抽屉）
    * **窄屏保护**：当内容区宽度 `< 360px` 时，强制切换为移动端布局（即使视口 `>= 768px`）
    * **CSS 实现示例**：
      ```css
      /* 移动端（默认） */
      .stage-container { flex-direction: column; }
      
      /* PC 端 */
      @media (min-width: 768px) {
        .stage-container { flex-direction: row; }
      }
      ```

### F. 思考过程 vs 评价面板切换
* **问题**：Stage 1 → Stage 2 时，思考过程内容被丢弃，评价内容直接覆盖。
* **对策**：评价面板在 **Stage 2 完成后** 才自动展开（仅首次），与项目简报保持一致。Stage 2 进行中时面板不会自动弹出。

### G. 排名显示格式
* **问题**：Stage 2 的最终排名如何显示？
* **对策**：从高到低排列，左侧显示 rank（如 🥇、🥈、🥉、4️⃣），右侧贴近边缘显示分数（如 9.2、8.7、8.3、7.9）。

### H. 评价面板内容
* **问题**：Stage 2 的评价面板显示哪些内容？
* **对策**：显示其他议员 + 自评的评价，每个评价独立显示，只显示评价文本，不显示分数。

### I. 无打字机效果
* **问题**：不使用流式打字机效果，如何处理生成过程？
* **对策**：直接显示完整文本，无需逐字显示。思考面板实时更新思考步骤，回答区域在生成完成后一次性显示完整内容。

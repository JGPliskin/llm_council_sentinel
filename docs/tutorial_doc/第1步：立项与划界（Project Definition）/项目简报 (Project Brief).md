### 项目简报 (Project Brief)

## 1. 背景与目标 (Why)

- 当前问题：当前 UI 风格不统一，缺少清晰的视觉语言（组件、间距、强调方式不一致）
- 重构目标：
    - 在 PC 端首屏范围内，Stage 3 默认可见且默认展开；Stage1/2 不抢占 Stage3 的视觉权重
    - HUD 规则：** Stage1/2 以 HUD 形式收敛呈现，Stage2 的评分结果固定展示在 HUD 底部摘要区
- 成功标准：
    - Stage2 的评价区域在完成后仅“首次自动展开一次”，用户关闭后不再强制打断
    - 全局视觉风格由 tokens + 组件清单驱动，不出现页面级“临时风格体系”

## 2. 范围边界 (Scope)

### ✅ 本次要做 (In Scope)

- **Stage3 前置与强化呈现**
    - Stage3 从页面末尾移至最前端（位于头像下方、Stage1 上方）
    - 增加 chairman 专属背景与 approved 印章 SVG（视觉强调，仅前端）
- **Stage3 失败降级（Fallback）**
    - Stage3 失败时触发备用模型（fallback）逻辑
    - 规则：沿用 Stage1/2 已存在的 fallback 机制（（同失败判定、同重试/降级策略、同层级实现）；仅允许“编排层”改动
- **Stage1 + Stage2 HUD 化合并展示**
    - Stage1 完成后出现「展开 Stage2 评论」按钮
    - Stage2 内容以“右侧非 overlay 面板（PC）/ 底部抽屉（移动端）”呈现
    - Stage2 完成后，在 HUD 底部摘要区展示评分结果（固定位置）
- **风格化与动效（限定范围）**
    - 不做暗色模式、不做键盘交互
    - 动效为“背包菜单式”的弹出/展开；提供“大叉”关闭 + 点击遮罩关闭
- **移动端退化方案**
    - HUD 在移动端以底部抽屉承载（避免信息挤压）

### ❌ 本次不做 (Out of Scope) - **重要！**

1. **后端只改“编排层”，不改 API shape**（字段名/层级不动），允许：**新增字段**
2. 先不做角色选择出战界面
3. 先不给议员回答配语音
4. 不引入大改信息架构（仅围绕 Stage 区域重排与呈现）

- **核心人员**：PM: 我, Design: 我, Gemini Dev: Codex, Gemini, Trae
- **里程碑**：
    - 2025/12/28：设计定稿 + **组件清单 + tokens + 关键页面高保真 + 关键状态**

## 4. 验收标准（Checklist）

*（历史需求已归档至文档末尾）*

### Stage3

- Stage1 不改变；Stage3 位于头像下方、Stage1 上方
- Stage1/2 未结束时，Stage3 显示占位文案：「主席正在聆听辩论」
- Stage1/2 结束后：
    - 若用户“接近顶部”（阈值：**一屏高度内**），Stage3 自动展开显示结果
    - 若用户已滚动到下方：**不强制跳转**，改为页面底部提示（Toast 或 FAB）引导用户回到 Stage3

### Stage1 思考面板（PC：右侧非 overlay）

- PC：Stage1 运行期间，在每个议员回答区域右侧显示"思考面板"（非 overlay）
    - 表现：面板显示思考过程，占用布局宽度，主内容区被挤压变窄（不覆盖、不遮挡）
    - 动效：面板展开/收起带"背包菜单式"动画
- 默认行为：思考面板可以打开/关闭，用户可以随时控制
- 内容：显示思考过程，包括思考步骤和时间戳
- 关闭方式：点击大叉关闭（PC 不要求遮罩；不要求 ESC）

### Stage2 评价面板（PC：右侧非 overlay）

- PC：Stage2 完成后，在每个议员回答区域右侧出现"评价面板"（非 overlay）
    - 表现：面板出现时会占用布局宽度，主内容区被挤压变窄（不覆盖、不遮挡）
    - 动效：面板展开/收起带"背包菜单式"动画
- 默认行为：评价面板在 Stage2 完成后 **仅首次自动展开一次**
    - 用户手动关闭后，本次运行不再自动弹出
    - 用户可以通过显式入口再次打开（入口位置：每个议员回答区域右上角/工具栏按钮，或 HUD 内统一按钮，二选一实现但需一致）
- 内容：显示其他议员 + 自评的评价，只显示评价文本，不显示分数
- 关闭方式：点击大叉关闭（PC 不要求遮罩；不要求 ESC）

### Stage1 思考抽屉（移动端）

- 移动端：思考过程以底部抽屉呈现（不做右侧面板）
- 默认行为：可以打开/关闭，用户可以随时控制
- 内容：显示思考过程，包括思考步骤和时间戳
- 关闭方式：大叉 + 点击遮罩关闭

### Stage2 评价抽屉（移动端）

- 移动端：评价以底部抽屉呈现（不做右侧面板）
- 默认行为同 PC：Stage2 完成后仅首次自动展开一次；用户关闭后不再强制弹出
- 内容：显示其他议员 + 自评的评价，只显示评价文本，不显示分数
- 关闭方式：大叉 + 点击遮罩关闭

### Stage1 HUD 进度条

- Stage1 运行期间，HUD 区域显示进度条
    - 显示当前进度百分比（如 50%）
    - 上方显示"生成中..."
    - 下方显示"X/Y 议员完成"（如"2/4 议员完成"）
- Stage1 完成时，进度条显示 100%，显示"生成完成"

### Stage2 HUD 进度条

- Stage2 运行期间，HUD 区域显示进度条
    - 显示当前进度百分比（如 75%）
    - 上方显示"评价中..."
    - 下方显示"X/Y 评价完成"（如"3/4 评价完成"）
- Stage2 完成时，进度条显示 100%，下方显示最终排名
    - 排名从高到低排列
    - 左侧显示 rank（如 🥇、🥈、🥉、4️⃣）
    - 右侧贴近边缘显示分数（如 9.2、8.7、8.3、7.9）

### 评分展示（HUD 底部）

- Stage2 完成时，评分结果固定展示在 HUD 底部摘要区
- 评分展示不应改变主内容滚动位置，不应触发强制跳转

## 5. 验收标准约束与假设（Constraints / Assumptions）

继续使用现有路由、继续支持 streaming、继续沿用现有组件库/不用换 UI 框架、
断点策略（可按现有实现微调，但需写死）：PC / 移动端使用响应式；移动端启用底部抽屉形态

### 选项卡设计

- Stage 1 和 Stage 2 使用相同的选项卡设计
- 选项卡位置保持不变
- 选项卡可以切换，点击时左侧回答区域和右侧面板内容同步切换
- 选项卡设计风格一致，不因 Stage 不同而变化

## 6. 风险与应对（Risks）

- **Streaming + 自动展开/不跳转**：可能出现竞态与 UI 抖动
    - 应对：定义统一状态机（stage 状态、展开状态、用户滚动状态）后再写 UI
- PC（非 overlay 挤压布局）在窄屏下易破版
    - 应对：设置最小内容宽度阈值；低于阈值时自动切换为"移动端底部抽屉"形态
